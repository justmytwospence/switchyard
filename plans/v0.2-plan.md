# Switchyard 0.2: owner-first bootstrap, passkeys and OIDC, plugin adapters out of core, GHCR release, homelab as pure config

## Summary

Make Switchyard a standalone product whose security never depends on the network or on one auth setup. The guarantee: a server is owned before it serves anything, and every enrollment is started by the owner, never by a visitor.

- **Sign-in:** add owner sign-in with passkeys (built in) and generic OIDC (any provider, bound to an explicit owner match).
- **Hosts:** they can self-enroll with a preset secret and never crash-loop.
- **Worktrees:** the folder for managed worktrees becomes a per-project setting.
- **Plugin adapters:** move from core into the pi-plugins packages that own the plugins.
- **Distribution:** releases publish to GHCR.
- **Homelab:** becomes configuration only. A pinned image, an Authelia OIDC client and `.env` values, so a fresh `up -d` comes up owned with no manual steps.

## Decisions

**Bootstrap**
- **Server-side init, not an "unclaimed" web state.** The owner exists before the server serves anything. Ownership is created by `switchyard init` (needs server access) or by declaring an OIDC owner in config. Rejected: a claim code shown to visitors, which announces an ownerless server and is visitor-initiated.
- **No visitor-initiated "request access".** Devices are added only by owner-initiated pairing (QR or link), or by owner sign-in (passkey, OIDC). Rejected: approval requests, which invite social engineering.
- **The startup bootstrap link is removed.** The coordinator no longer mints an enrollment on start. When not set up, it prints and logs only the hint "Not set up yet: run `switchyard init` on this server".

**Sign-in**
- **Passkeys:** `@simplewebauthn/server` and `@simplewebauthn/browser` (14.x). They are standard and maintained, and an owner credential needs no identity provider.
  - Discoverable credentials, user verification "preferred".
  - RP ID = the public URL's hostname.
  - Disabled, with a stated reason, when the public URL is not HTTPS (localhost excepted) or its host is an IP address.
- **OIDC:** `openid-client` 6.x (panva). It is standards-based, so any provider works (Authelia, Authentik, Keycloak, Pocket ID, Google).
  - Authorization code flow with PKCE, state and nonce.
  - Claims are merged from the ID token and userinfo, because Authelia puts email and groups in userinfo by default.
  - The owner match is mandatory: subject, verified email, or group. The coordinator refuses to start when OIDC is configured without one.
- **The coordinator-issued device credential stays the only request credential.** Passkey and OIDC only mint a device. An expired IdP session never breaks the PWA, push or WebSocket. Rejected: forward-auth header trust, which is setup-specific and easy to misconfigure.
- **PWA OIDC uses a handoff.** iOS Home Screen apps have their own cookie jar; an external IdP redirect completes in Safari's view, not in the app. So in standalone display mode the app starts a flow, opens the authorize URL, and claims the minted credential with a one-time poll token. Browsers use the direct redirect flow.

**Hosts**
- **Shared-secret self-enrollment, opt-in.** `SWITCHYARD_HOST_ENROLL_SECRET`, at least 32 characters, enables `POST /api/hosts/enroll {secret}`. Each host it creates is still individually revocable. Rejected: hosts asking to join and waiting for approval (visitor-initiated).
- **A host without config waits instead of exiting.** It auto-enrolls when a secret and coordinator URL are set. Otherwise it logs the exact enroll command and polls for `host.json`.

**Network**
- **Trusted proxies are explicit.** Fastify `trustProxy` comes from `SWITCHYARD_TRUSTED_PROXIES`, a comma-separated list of IPs and CIDRs, default none. The current `trustProxy: true` lets any client spoof `X-Forwarded-For`, which matters now that rate limits key on IP.
- **Public auth endpoints get a small in-process limiter.** Fixed one-minute window per IP and route group, returning `429 rate_limited`. Rejected: `@fastify/rate-limit`, a dependency for about 40 lines.

**Separation**
- **Plugin adapters live in pi-plugins.** Location: `packages/<pkg>/src/switchyard/adapter.ts` plus `switchyard-adapter.json`, declared from the pi-plugins root `package.json` `switchyard.adapter`. They are loaded by the host through the existing plugin tier.
  - The `.ts` files are imported with Node's built-in type stripping (Node ≥24, files outside `node_modules`).
  - They have zero imports, because the `@switchyard/*` packages are not published and pi-plugins' contract test forbids imports leaving a component.
  - Rejected: keeping them bundled in Switchyard core, which couples core to one person's plugins.
- **`@switchyard/adapter-examples` becomes documentation.** It keeps one example adapter (`hello`). The host agent no longer loads bundled adapters by default (the tier stays and defaults to `[]`), and the image no longer ships adapter-examples.
- **Real-plugin compatibility tests move to `packages/host-agent/test/compat/`.** They load the pi-plugins suite through an isolated `settings.json` `packages` entry, which is the production discovery path.
- **Worktree folder: `Project.worktreeDir`, default `.worktrees`.** It must be a relative path inside the checkout: not absolute, no `..` segments, no leading `/`. It is passed to host commands. Rejected: absolute or templated paths (the spec requires repo-local worktrees).

**Release**
- **GHCR image** `ghcr.io/justmytwospence/switchyard:<semver>` plus `latest`, built multi-arch (amd64, arm64) on `v*` tags.
- **The repo and package stay private, as the user chose.** The NUC pulls with its existing ghcr.io docker login.
- **Every package version goes to 0.2.0**, and the root `package.json` gets `"version": "0.2.0"`. `AGENT_VERSION` and `COORDINATOR_VERSION` read their `package.json`.

**pi-plugins checkout**
- **Wrap up the dirty working tree first,** as the user asked. Review the uncommitted changes, run checks, commit them as logical conventional commits, then rebase on `origin/main`. Only then add the adapters.

**`src/oidc.ts`** (new): `class Oidc(store, owner, config, auth)`, built on `openid-client`.
- **Config** (`config.oidc`): `{issuer, clientId, clientSecret|null, label, scopes, owner: {subject|null, email|null, group|null}}`.
- **Discovery:**
  - `client.discovery(new URL(issuer), clientId, clientSecret ?? undefined, clientSecret ? undefined : client.None(), loopbackHttp ? {execute: [client.allowInsecureRequests]} : undefined)`.
  - `loopbackHttp` means the issuer protocol is `http:` and its host is `localhost`, `127.0.0.1` or `::1`.
  - Lazy and cached. A failure is cached for 30 seconds and surfaced as `status: "error"`.
- **`begin({deviceName, kind, next, handoff}) -> OidcBeginResponse`:**
  - `next` must start with `/`, not `//`. Otherwise `/` is used.
  - Creates the PKCE verifier, `state` (the flow id is a `newId("enr")`-style random) and `nonce`.
  - When `handoff` is set, also creates `pollToken = newToken()` and stores `pollTokenHash`.
  - Stores the flow (kind `oidc`, 10 minutes, data `{verifier, nonce, deviceName, kind, next, handoff, pollTokenHash, result: null}`).
  - `authorizeUrl = client.buildAuthorizationUrl(cfg, {redirect_uri: publicUrl + "/api/auth/oidc/callback", scope, code_challenge, code_challenge_method: "S256", state: flowId, nonce})`.
- **`callback(currentUrl: URL)`:**
  - Loads the flow by `state`.
  - Runs `client.authorizationCodeGrant(cfg, currentUrl, {pkceCodeVerifier, expectedState, expectedNonce})`.
  - Merges `tokens.claims()` with `client.fetchUserInfo(cfg, access_token, claims.sub)`. Userinfo failure is ignored when the ID token already has the needed claims.
  - **Owner match:** every configured criterion must hold.
    - Subject: `sub === subject`.
    - Email: `email` matches case-insensitively and `email_verified !== false`.
    - Group: `groups` (array) includes `group`.
  - On mismatch, throws `forbidden` with message `Signed in as <preferred_username|email|sub> (subject <sub>), which is not this server's owner.`
  - On success, `auth.createDevice(deviceName, kind, "oidc")`.
  - Return value:
    - Not a handoff: `{mode: "direct", credential, next}`.
    - A handoff: stores `result: {deviceId, credentialEnc}` in the flow (the credential itself; the row expires in 10 minutes and is deleted when claimed) and returns `{mode: "handoff"}`.
- **`claim(flowId, pollToken)`:**
  - The flow and the `pollToken` hash must match. Otherwise `unauthorized`.
  - Returns `{status: "pending"}` until a result exists.
  - Then deletes the flow and returns `{status: "done", deviceId, credential}` for the route to set the cookie.
- **`describe()`** returns `AuthMethods.oidc`. `ownerMatch` is a readable string such as `email spencer@… and group admins`.

**`src/rate-limit.ts`** (new): `class RateLimiter(limit, windowMs, clock)` with `hit(key): boolean`.

- Sweeps expired keys every 1000 hits.

- Key is `req.ip`. Over the limit throws `rate_limited` "Too many attempts; wait a minute and try again".

**Pitfalls**
- **OIDC redirect URI:** it uses `config.publicUrl` and must exactly match the Authelia client's redirect.
- **Cookie and trusted proxies:** the cookie's `secure` flag and the trusted origins derive from `publicUrl`, never from forwarded headers. Keep it that way when adding trusted proxies.
- **Handoff page:** the handoff callback page must not set the cookie, otherwise two browser contexts share one device credential.
- **Type stripping:** Node refuses it inside `node_modules`. pi-plugins git installs are outside it. If someone installs a plugin via npm, a `.ts` adapter fails to load with a clear diagnostic (the registry already records load errors).
- **Concurrent edits:** do not run `biome --write` across packages owned by another worker during parallel work.

**Most likely to be wrong**
- **The exact `openid-client` v6 call shapes** (`discovery` arguments, `None()`, `allowInsecureRequests`). Check its README for the installed version.
- **The `@simplewebauthn` v14 option names** (`optionsJSON` in the browser helpers).
- **Authelia client keys** in the version the NUC runs. Mirror the omnigent entry rather than these names.
- **iOS PWA behavior for `window.open` to the IdP.** The handoff poll makes it work in either case, but verify on the phone.
